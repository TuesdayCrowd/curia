## What this is, in one paragraph

A writer of a lifecycle row reads the log after its append and refuses to report an act the Forum's fold skips (R4.42; `KeyActs.AppendAsync`, `src/Curia.Application/Credentials/KeyActs.cs:295-318`, the refusal at `:315`, built by `KeyActErrors.NotHonoured(index, predicate)` at `:167-169`). The routes map that refusal to `500` through `StatusForKeyAct`'s default arm (`src/Curia.Api/ForumEndpoints.cs:3667`, `:3706`; called at `:3502` and `:3557`), and `ServerFault` serves type and title and drops the detail, which is where the index was (`src/Curia.Api/ServerFault.cs:16-31`; R11.33). The client then treats it as any server fault: `curia rotate` reaches `RefusedAsAgentAsync` (`src/Curia.Client.Cli/Program.cs:2114`) and exits 8; the key it generated (`:2071`, a `using` `ECDsa`) is disposed and never written; the profile is byte-identical (`ProfileStore.CompleteRotation`, `src/Curia.Client/ProfileStore.cs:528-553`, is called only on a `201`, `Program.cs:2102`); `curia retire` the same (`:2191`, `:2214`). `curia keys` then prints the **first** `SKIPPED` words for the profile's own row ("If this profile did not make it, report it", `src/Curia.Client/KeysReport.cs:122`), because the second form needs an act recorded at that index (`:118-120`). The row is permanent and is decided again by every fold: **when the defect that skipped it is fixed, a rotation's key becomes live and nobody holds it** (it counts against the live-key ceiling and only its own signature can retire it, R4.39), **and the owner's next `curia keys` or `curia rotate` reports its own rotation as `FOREIGN`** (`LifecycleWatch.Compare`, `src/Curia.Client/LifecycleWatch.cs:44-58`: an index in the lifecycle that the profile did not record). The fix: the `500` names the row's log index as an integer member (R4.44); the client records the act in a third state, **made and not in force**, without moving its signing key, and keeps the key the rotation generated beside it so `curia retire` can end it (R11.98); `curia keys` and `curia_keys` say when such an act has come into force (R11.96 (add.)).

## What the reading found that the register item did not say

1. **The index is already computed; only the wire drops it.** `KeyActs.AppendAsync` has the index from the log it read after the append (`:309-310`) and puts it in prose (`:170`). The route cannot read prose (and must not: ruling 2), so the index needs a typed carrier from `Error` to `ServerFault`. `Error` is a sealed positional record of three strings (`src/Curia.Domain.Primitives/Error.cs:11`).
2. **Precedent for a number in a refusal is prose, and that precedent does not transfer.** Budget refusals carry `next_slot_at=` inside `detail` and the client reads it by prefix (`ForumEndpoints.cs:1605`; `ForumClient.cs:549-559`). A 5xx has no detail (R11.33). So the member is the first non-`type`/`title` member a 5xx carries, and R11.33 needs an `(add.)` that names it and closes the door behind it.
3. **The client keeps a 5xx's document already.** `ForumClient.Classify` returns `new Refusal(kind, status, error, document)` for every status (`src/Curia.Client/ForumClient.cs:565-568`), so `refusal.Document` carries `log_index` with no change to the transport.
4. **The key must outlive the `using`.** `generated` is `using var` at `Program.cs:2071` and an `InProcessSigner` wraps it (`:2078-2079`, disposed in `finally` at `:2117-2120`); the external-signer path keeps only a command (`:2083-2093`). Keeping the key means writing its PKCS#8 under `keys/` (the derived name `RetainedKeyName(kid)`, the rule `ReadRetained` enforces at `ProfileStore.cs:674-676`) before the `finally`, or recording the signer command.
5. **Keeping the key makes `curia retire` the remedy with no new verb.** `RetireKeyAsync` accepts any retained key that is not retired (`Program.cs:2166-2170`, after refusing the current key at `:2160-2164`) and `LoadRetained` loads it from its file or signer (`ProfileStore.cs:587-617`). A kept key recorded as a `RetainedKey` is retirable the moment the Forum honours its rotation, and refused by the Forum until then (an unbound key: `KeyActErrors.UnknownKeyType`, 404, or `NotLive`, 409; nothing appended: Task 0 R1's control confirms which).
6. **A record nobody reads is a quiet record.** If the third state is only a member in `identity.json`, nothing changes behaviour on it: `KeysReport` already prints the second form for *any* recorded act at a skipped index (`:117-120`), whatever its state. So the state needs a reader that would go wrong without it: `NOW IN FORCE` (R11.96 (add.)) reads it, and the `in_force: true` control (NHR9) is what shows it is read.
7. **A recorded index can hide a stranger's entry.** `LifecycleWatch.Compare` skips FOREIGN for any recorded index (`LifecycleWatch.cs:51`). An index taken from a `500` that is wrong (a Forum fault, or a 500 from something that is not the Forum: the `IsForumProblem` check applies to `403` only, `ForumClient.cs:542-543`) would mark a later stranger's rotation at that index as the profile's own. So a not-in-force act counts as the profile's at an index the lifecycle now holds **only if the key bound (rotation) or retired (retirement) there is the kid the act recorded**; otherwise the entry is FOREIGN as today (ruling 7; NHR9b; FNHR10).
8. **The same loss has a second, likelier door, and it is not this item.** `AppendAsync` reads the log again after a successful append (`KeyActs.cs:309`); a fault of that read returns `LogUnreadable` (`:310`), which the route maps to `503` (`ForumEndpoints.cs:3705`) **with the row appended and, absent a defect, honoured**. The client discards the key there too, and the owner's next verb reports its own rotation as FOREIGN. No verifier defect is needed, only a read fault. `[read, not run]`: Task 0 R3 measures it, and it is filed as item 322 (gate: before the guard's lift), not built here (ruling 12).
9. **A later act over a skipped one can be undone by the fix that honours the first.** The fold decides every row against the honoured prefix (R6.64, `broken-link`). An honest rotation made after a skipped one links from the last honoured entry; when the fold changes and honours the first, the later row's `prev` no longer names the last honoured entry and it is skipped. The profile would then sign with a key the Forum no longer binds. `[read, not run; the fold's text at src/Curia.Application/Credentials/LifecycleFold.cs:233, :264]`. Filed as item 323 (non-property (c)); the R11.98 words tell the agent to report before acting again, and `curia rotate` does not refuse (ruling 8).

## The design

**Application (`src/Curia.Application/Credentials/KeyActs.cs`).** `KeyActErrors.NotHonoured(index, predicate)` sets the index as a typed value on the `Error` it returns (below); its type, title and detail are unchanged, so `curia-operator compromise` (`src/Curia.Operator/Program.cs:1305`) and LRV43 (`tests/Curia.Application.Tests/Credentials/WritersRoundTripTests.cs:132-160`) are untouched. The writer stays a failure: a skipped row is never an `Ok` (ruling 2).

**Primitives (`src/Curia.Domain.Primitives/Error.cs`).** One init-only property outside the positional parameters: `public long? LogIndex { get; init; }`, documented as "the log index of a row a refusal is about, composed by the Forum (R4.44); read only where a requirement names it". Record equality includes it; every existing `Error` has `null` (Task 0 R6 greps `Assert.Equal(` over `Error` values to show none breaks). **Alternative, if Task 2 finds the property reaches further than counted:** a typed carrier in Application (`NotHonouredRow(long LogIndex, string Predicate)`) returned beside the failure. Either is acceptable under ruling 2; the property is the default because it adds no call-site type.

**Api (`src/Curia.Api/ForumEndpoints.cs`, `src/Curia.Api/ServerFault.cs`).** `Problem(status, error)` (`ForumEndpoints.cs:3289-3296`) passes the error to `ServerFault` as now; `ServerFault.ExecuteAsync` writes `{type, title, detail: null, log_index}` **only when `error.Type == KeyActErrors.NotHonouredType` and `error.LogIndex` is a whole number ≥ 0**, and `{type, title, detail: null}` for every other 5xx, whatever `LogIndex` holds (ruling 3; Task 0 correction 1: the wire already carries `"detail":null`). The members are composed by one **public pure type `ServerFaultBody`** in `Curia.Api` (CS-5: `ServerFault` is `internal` and `Curia.Api` grants no `InternalsVisibleTo`, Task 0 R7.1; `ServerFault.ExecuteAsync` calls it), so NHR2 drives it without a new grant. It serializes to today's bytes for every body today's code writes: the four whole-body tests stay unedited and green. The detail is logged as now (EventId 5000). The `201` bodies are unchanged.

**Client library (`src/Curia.Client/ProfileStore.cs`).**
- `LifecycleAct(string Kind, string Kid, long LogIndex, bool InForce = true)`; rendered with `"in_force": false` only when false (so every profile written today renders byte-identically); read: absent is `true`, `false` is `false`, any other value is `MalformedProfile("a lifecycle act's in_force is a boolean")`.
- `RetainedKey(..., bool Retired = false, bool RotationInForce = true)`; rendered `"rotation_in_force": false` only when false; read the same way.
- `ProfileStore.RecordNotInForceRotation(profile, newSigner, newPrivateKey, long? logIndex)`: writes the new key's PKCS#8 to `keys/<RetainedKeyName(kid)>.pem` at 0600 (or records the external signer's command), adds it to `retained_keys` with `rotation_in_force: false`, adds `LifecycleAct(Rotation, kid', i, InForce: false)` when `logIndex` is a whole number ≥ 0, writes `identity.json`; **does not touch `Kid`, `Alg`, `Signer`, `signing-key.pem` or the cached token** (the old key still signs and its token is still good).
- `ProfileStore.RecordNotInForceRetirement(profile, kid, long? logIndex)`: adds `LifecycleAct(Retirement, kid, i, InForce: false)` when the index is valid; the retained key's `Retired` stays false.
- `KeysReport.Of` gains the `NOW IN FORCE` line (R11.96 (add.)), and `LifecycleWatch.Compare` counts a not-in-force act as recorded at an index only if the key set binds (rotation) or retires (retirement) **the act's kid** there (ruling 7); otherwise the index is not the profile's and the entry is `FOREIGN` (Amendment 2 ruling 2).

## Rulings (decided, not asked)

1. **`500` stays** (PR N ruling 122): a `4xx` blames the request; a `503` invites a retry, and every retry appends another permanent row. The type and status do not change; one member is added.
2. **The index is typed from the writer to the wire and never parsed from prose.** A route that recovered the index from `detail` would make the detail's wording a contract nobody wrote down. And a skipped row is never an `Ok` value with a flag: a caller that forgot the flag would report success, which is the fail-open R4.42 exists to prevent.
3. **One 5xx type carries one member; the rule is written at `ServerFault`, not at the route.** R11.33's reason (a component's words) does not reach an integer the route composes from the log it read; but a general "5xx may carry members" is the next adapter's door. `ServerFault` writes `log_index` for `curia/keys/not-honoured` alone (NHR2; FNHR5). `curia/acts/not-honoured` (operator acts) has no route (`ForumEndpoints.cs:3665`) and gains nothing.
4. **The predicate is not on the wire.** The key set already states it for the row (`curia_skipped`, R4.41), and the client prints it from there in the second form. One member, one source for each fact.
5. **Not `CompleteRotation`** (ruling 122): it would make the new key the signing key, and the Forum does not bind it. The profile's signing key and `signing-key.pem` are untouched byte for byte, and the token the verb requested and cached before the refusal is kept, not deleted (`CompleteRotation` deletes it; Task 0 correction 2: a refused verb leaves `token.json`); NHR3 asserts both.
6. **The key is kept even when the index is not usable.** A `not-honoured` answer says a row was appended; whether the client can record *where* is a second question. A missing or malformed `log_index` (absent, `null`, a string, negative; Amendment 3 ruling 1: a number that is not an integer or is out of range makes the whole problem document one the profile refuses, which is unreadable and keeps nothing, NHR6b) records no act and still keeps the key with `rotation_in_force: false` (NHR6), because the key is what makes a later live key retirable. Every **other** refusal keeps nothing (NHR7; FNHR6), and so does a problem document the profile refuses (NHR6b; FNHR15): an answer the profile refuses does not say a row exists. The scope is the one answer that says a row exists.
7. **A not-in-force act is the profile's own at an index only if the kid matches** (finding 7). `NOW IN FORCE` prints when the published lifecycle holds the act's index and the key set binds (a rotation) or retires (a retirement) the act's kid there. When it holds the index for another kid, the entry is FOREIGN, and the act is neither NOW IN FORCE nor MISSING (its index is published, and MISSING's words say it is not; an in-force act at a published index is not MISSING either; Amendment 2 ruling 2). This narrows the trust the third state places in a `500`; it is not applied to in-force acts recorded from a `201` (unchanged; non-property (a)).
8. **`curia rotate` and `curia retire` do not refuse while an act is not in force.** An owner may need to rotate a compromised key now, and the operator's declaration is not theirs to make. Finding 9's hazard is said in the R11.98 words (report before acting again) and filed (item 323); a refusal would lock an owner out of its own lifecycle for as long as a permanent row exists.
9. **`curia-mcp` moves to 0.12.1.** `ToolCatalogue.Version` is "bumped when the served tool surface changes" (`ToolCatalogue.cs:42`), and R11.94 (errata G63, 0.11.1) set the precedent that words a tool returns are its surface. `curia_keys` gains a line kind and its description a sentence. No tool, argument or schema changes, so a patch bump.
10. **Exit 6, not 8.** Exit 8 says "a check could not be run" and reads as "try again later" (`Help.cs:451-458`); a retry is the harm. ## Open risks (named so the reviewer can look)

1. **`Error.LogIndex` widens a domain primitive.** Every `Error` now has a field almost every caller ignores. NHR2 and ruling 3 confine its effect on the wire to one type; nothing confines who sets it. If the reviewer prefers the typed carrier, Task 2's alternative is named and costs one more type.
2. **The kept key is a private key on disk that the Forum may never bind.** It has the profile's mode and directory, as a retained key does. A profile that accumulates kept keys from repeated defects accumulates keys; R11.98's words tell the agent to report rather than retry.
3. **`NOW IN FORCE` depends on the key set's `curia_log_index` and `curia_retired_log_index`** (the same members `LifecycleWatch` reads). A Forum that serves a lifecycle without them yields no line, as it yields no `FOREIGN` today.
4. **The words are long.** The cold read is the check; a failed gate is an amendment to the words, and the errata's R11.98 words move with them.
5. **Finding 9 is from reading.** If the fold does not break the later link as read, item 323 is restated by whoever measures it.
6. **`ServerFaultBody` is a new public type in `Curia.Api`** (CS-5's pattern, no `InternalsVisibleTo`). Anything may now call it; nothing but `ServerFault` should. NHR2 pins what it returns, and the four whole-body tests pin that today's bodies are byte-identical through it.
