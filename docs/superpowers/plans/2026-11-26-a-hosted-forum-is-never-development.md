## What this is

## The rule's exact condition (rulings 1 to 3)

**1. Refuse when both hold: (i) the host's environment is Development; (ii) the public origin's host is not loopback.**

- *Environment.* The name the host itself resolved (`builder.Environment`, which is `ASPNETCORE_ENVIRONMENT` then `DOTNET_ENVIRONMENT`, or a test host's `UseEnvironment`), compared the way the framework compares it: `IsDevelopment()`, ASCII case-insensitive `Development`. This is deliberately the framework's own predicate: the page is added by the framework when that predicate holds, so the guard cannot disagree with the page about when it exists. `development` and `DEVELOPMENT` are refused; `Staging` and any custom name are not (no page exists there; non-property a). **No Forum setting names the environment**; the guard reads no `Curia:*` key and no variable of its own. An unset variable is Production, so an unset host starts.
- *Public origin.* Every Forum holds an origin (R11.109 refuses a start without one), so "holds a public origin" means "an origin whose host is not loopback". The origin is already a canonical string (R11.109's grammar), so the test is on three exact spellings and nothing is resolved or parsed again: host equals `localhost`; or a dotted-decimal host whose first octet is `127` (all of 127.0.0.0/8); or the host is `[::1]`. **Everything else is public, refused:** `x.localhost`, `0.0.0.0`, RFC 1918 and tailnet addresses, `[::ffff:7f00:1]` (the canonical rendering of the mapped loopback; the owner's wording was "non-loopback" and a name the grammar renders differently is not named loopback), any DNS name. The scheme is not read: `http://198.51.100.10` is public and `https://localhost` is not. The port is not read.
- *Why the origin and not the bind address.* The owner's ruling is on the origin, the Forum knows its origin from R11.109 and does not know which interface a proxy or `ASPNETCORE_URLS` exposes. The unit binds `127.0.0.1` and the origin is the public name; the origin is the signal that discriminates the hosted shape. Stated as non-property (b).

**2. Where it runs: inside the one registration of `PublicOrigin`.** `Program.cs`'s `AddSingleton(_ => PublicOrigin.Read(...).Match(...))` factory gains one call, `HostingGuard.Check(builder.Environment.EnvironmentName, origin)`, whose failure throws the same `InvalidOperationException` by the same expression. Consequences, each a reason: nothing can obtain a `PublicOrigin` without passing the guard (every URL, `aud`, `iss` and the `Host` filter reads it), so the guard cannot be skipped by a new composition path; the refusal comes with R11.109's, before a request, before the eager `GetRequiredService<PublicOrigin>()` returns, and before a store is read (DEV5 proves the order against a dead connection string); and item 393 later fixes every start refusal at once, this one included.

**3. No door.** The guard has no opt-out: no key, no variable, no service to replace in production code. See ruling 4 for the fixtures.

## Refusal words, and where they come from (ruling 4's twin)

One definition: `src/Curia.Api/HostingGuard.cs` holds a `Words` constant with `{Origin}` and `{Environment}` holes, as `PublicOrigin` holds its sentences; the runbook's "What a refused start looks like" quotes it and a probe reads the runbook's quotation against the source (DPK3's method: the doc is read from the file, the words from the code, and an edit to either alone fails the build). Draft (Task 7's cold read decides the final):

> `The Forum is started in the Development environment and its public origin is "https://forum.example", which is not this machine's loopback address. In Development the host serves a developer exception page that carries a request's Authorization and DPoP headers and the access token, so a Forum reached by any other name must not run there. Set ASPNETCORE_ENVIRONMENT to Production, or leave it unset, and start again. (Local work: set Curia:PublicOrigin to http://localhost[:port].) No setting lifts this (R11.112).`

Rules for the words: the origin is quoted because its grammar admits no userinfo (R11.109's own `@` refusal ran first; DEV6b proves the guard is never reached with a value that carried one); the environment is named as the variable and never echoed (the framework's name is whatever case was spelled); the fix named first is the hosted fix (Production), the loopback origin second and parenthesised, so a reader at a hosted box does not "fix" it by renaming the Forum `localhost` (which would answer every request `host-not-served`, loudly, and mint tokens for a name nobody dials: G82 non-property (b)); type `curia/config/development-with-public-origin` (the `curia/config/` family `PublicOrigin` uses); no stack of values beyond those two. The text appears in the unhandled exception's message, which is what a systemd journal shows today for R11.109 (item 393).

## Fixtures: Production, no door, with a probe that the suite can fail

`WebApplicationFactory` defaults to Development (D125 Task 0, finding 0.5), so every `ForumFixture` is Development unless it says otherwise. Read from the sources, three fixture shapes:

- **Loopback origins (unaffected, stay Development):** `ForumFixture` itself (`http://localhost`), `UseReservedKestrelPort()` (`http://127.0.0.1:<port>`), and every fixture that does not override `PublicOrigin`. That is the large majority, including every fuzz, burst and body-bound row, and the page's own probes (BND6's Development fixture keeps the page reachable by its own explicit `UseEnvironment("Development")` on a loopback origin).
- **Public origins (must change):** `OriginFixtures.cs`'s `HttpsNamedForumFixture` (`https://forum.test`) and the fixtures there that name themselves, `OriginVariantTests.cs`'s IDN fixture (`http://xn--bcher-kva.example`), `ProxiedKestrelForumFixture` (the proxy's address), `RunbookMonitorLineTests`' fixture (`forum.example`), `OriginSettingFixture` (ORG1 to ORG3 set any origin), `OriginBindingTests`' `WithWebHostBuilder(... "http://other.example")`, and `RoleForumFixture` (already Production).
- **The choice.** These fixtures run **Production**, set where each names its origin: `ForumFixture` gains one protected virtual, `HostingEnvironment` (default `null`: the factory's own, Development), and a fixture that overrides `PublicOrigin` with a non-loopback value overrides `HostingEnvironment` to `"Production"`. Not an opt-out door like the hashed embedder's, for two reasons. (i) The embedder door exists because production has no second embedder and a test cannot afford the model; here the *production* behaviour in the shape under test **is** Production: a fixture that holds a public origin and runs Development is exactly the shape the rule refuses, and a door would keep the suite running the shape the hosted Forum may not, discharging nothing about the hosted one. (ii) A door is a code path the hosted Forum would also carry, and the rule's whole value is that no path lifts it; a fence over "production code cannot open the door" is a second control to keep green where there is no door to fence. The cost: these fixtures' Development-only behaviour (the page) is lost, and Task 0 measures that it is not relied on: run each affected class once in Development (before the rule, as today) and once in Production and compare the pass sets (a difference is a finding, not a fixture change).
- **The suite must be able to fail on this (DEV9).** A probe subclass of `ForumFixture` with a non-loopback `PublicOrigin` and no `HostingEnvironment` override is started, and the start must fail with the guard's type and words. Without it every fixture passing proves only that every fixture was edited, and a future fixture that forgot is caught by its own start failing; DEV9 is what shows that failure is the guard's and not some other.
- **Reversal if Task 0 finds the Production run differs:** the plan stops and asks. The alternative is a test-only replacement of the environment the guard reads, which is a door in all but name and so changes ruling 3.

## Item 393: left alone (a decision, with its reasons)

Folding it in would make every start refusal exit cleanly (a caught exception, a short line, a chosen exit code, no stack trace and no abnormal exit that a host may write a core for). Left alone, because: (1) **the rule's correctness is independent of how a refusal is presented**; D125 shows the cost of stretching a small stage to a neighbour's surface: here the neighbour changes `Program.Main`, the exit codes the runbook, the unit's `Restart=` and the readiness script quote, and every R11.109 probe's expectation, which is a stage with its own probes, its own live run and its own cold read; (2) it would put the owner's "before announcing" on the critical path of a stage whose own risk is the fixture change; (3) **the new refusal is built to be fixed with the others**: the same `InvalidOperationException`, thrown from the same factory, so item 393's later fix has one site, and DEV10 fails if this stage makes it two; (4) the stack trace holds no secret the guard adds: the only value in the message is the origin, which R11.109's grammar already refuses to hold userinfo for (Task 0 (6) confirms by reading a real start's output, and if it finds a value in a trace that is not the origin, the stage stops and reports). What the stage does for 393: its Task 7 cold read tests the words in the raw trace form, so the words are known to work *as they print today*, and item 393's Task 8 note gains a line "Item 399 (c)'s refusal is a second start refusal and is covered". **Reversal:** if the owner would rather announce with a clean exit, 393 is its own stage next, small, and this one's words do not change.

## Open risks

1. **Production fixtures may differ from Development ones.** Task 0 (3) measures it; a difference stops the plan before Task 3.
2. **The set of affected fixtures is found by running, not by grep:** `WithWebHostBuilder` calls and string-built origins are missed by grep. Task 0 (2) logs every host's origin and environment for one suite run; the rule's own start failure then finds any that remain, which is DEV9's point and the cost of a wrong list is a red suite, not a silent pass.
3. **`builder.Environment` vs the test host's environment.** `UseEnvironment` in `ConfigureWebHost` may apply after `builder.Environment` is read in `Main`; Task 0 (4) reads which; if they differ the guard reads the built `IHostEnvironment` through the service provider in the factory (`sp.GetRequiredService<IHostEnvironment>()`), the same value the page uses.
4. **`IsLoopback` on a canonical string** rests on R11.109's grammar (lower-case, no trailing dot, canonical IPv6); a change there moves this. DEV2's table is written from the grammar's own rows (PublicOriginStartTests' accepted list), so it is not derived from `IsLoopback` (vacuity question 4).
5. **A hosted Forum whose operator sets Development to see errors** is told by the refusal and nothing else; that is the rule working. The runbook points to the journal and `curia keys`-style diagnosis instead.
