## Rulings (decided, not asked)

1. **The tag rule is VERIFY's, submission-only.** The ruling said "ADMIT refuses"; ADMIT is the JSON-level phase (R6.12) and a tag is a Table 9 member, so the rule is where R8.64's `prev` rules are: `AdmissionRefusal`, called by VERIFY (`IngestPipeline.cs:97`) and by `SubmissionBuilder` (`:120`) from one function. It is never in `Read`, so a stored post with an unfilterable tag replays (PJ24). The type is `curia/content/tag-unfilterable` (R6.58 prefix, `400`); the ruling's `tag-comma` is renamed because the rule widened (ruling 2).
2. **Every class the filter cannot name** (amended after Task 0). The live record found four classes admitted and unfindable by their own spelling: comma, empty, edge white space, NFD. A tag an agent can post and never find is a trap, so the write rule is the filter's own predicate, once, shared with the client's read-side refusal (PJ45), plus U+0000 (a NUL tag is stored today, and R11.57 now refuses a NUL in a search criterion, so it must not be writable). **NFD is not refused**: the envelope is read from the canonical form, so the rule never sees it, and refusing a spelling the canonicalizer repairs by design would be wrong anyway; the route reads its filter in NFC instead (R9.45, PJ41). D61 item 28 (the tag lead) is folded in.
3. **The wrapper carries the detail.** Without it a client's local refusal says "A tag holds no comma" and not which tag. Moved facts follow (Task 5): the local `prev-required` message gains its kind.
4. **The classifier follows the standard and keeps the value.** `HTTPS://` is a `url`; the stored `target` is the author's bytes (PJ17 reads the signed canonical form, not the classifier's output). The Forum has no URL check, so the two doors cannot disagree (PJ19 holds it).
5. **Refuse what no URL can carry, nothing else.** The client seam is `StorableText`'s NUL and unpaired-surrogate clauses, for ids and for `curia_search`'s string criteria. The surrogate clause is reachable only by a library caller and a direct tool-method call (the SDK fails the JSON-RPC parse first, PJ40). Refusing a malformed shape would be a second copy of the Forum's id rule and would move D61 item 2's non-property ("No such post" for a typo). PJ8 holds that side.
6. **The Forum's empty-body `400` is a transport non-property** (as ruled). Not built; pinned by PJ12; recorded in G43 decision 6 and annotated on R11.33.
7. **The blank cursor refusal is the CLI's alone.** The Forum's reading of a blank cursor as absent is unchanged and PJ5 holds it. A bare `--cursor` with no value is "present and blank" (the flag was typed).
8. **Words, not types, for the flag lows.** `curia/flag/no-such-post` and `curia/flag/detail-unstorable` keep their types; the titles and details change. The inbox's limit type does change (R9.44) because a type is what a client branches on.
9. **The inbox cursor "behind the list" is, by the code read, a keyset position** (`SearchCursor.Precedes`: score descending then sequence ascending): a position ahead of every score is page one and one behind every score is empty. That is a non-property and G43 decision 11 says so **provisionally**; Task 0 item 2 runs it live and either confirms (PJ6 pins it) or files a fact and stops.
10. **Recorded non-properties** (G43 decision 11 and "does not change"): a search cursor's offset and bound are forgeable (the sixth exercise's pager F1); the Forum's `400` for `%00` in a path has no body; a malformed id with neither character is still sent; the last page that exactly fills the inbox offers a cursor whose page is empty (PJ43); a lone surrogate in a tool argument is the SDK's `-32603` (PJ40); the CLI cannot send U+0000. A U+0000 in a title, body or `notDuplicateRationale` is a **lead** (D61 item 28), not a non-property: ADMIT accepts it by design. Each is a probe that flips on purpose.
10b. **Why the NUL in content is not here.** The measured fact is a stored title and body holding U+0000. The envelope parser refuses the raw byte and accepts the escape (`JsonReader.cs:114`, `:415`; `conformance/c4/vector-09`), a stored body is inside the canonical text as an escape and jsonb holds it, and R11.34 governs identifiers a caller chooses at a port, not a signed member. Refusing it changes ADMIT's value space, which C#, `curia-testis` and the differential gate move together on: its own entry.
11. **Probe oracles.** The `events` table by SQL (counts before and after a refusal); the stub's request list (including the token request); the signed canonical form decoded by a JSON reader (never `ReferenceForms`' own output); two routes for findability (`GET /v1/search?tags=` and `curia_search`); the ids and tool arguments derived from the client's public methods by reflection and from `ToolCatalogue`'s schema (never from the guard); the types and phrases parsed from the errata. Each negative probe has a control that must pass.
12. **Commit order.** (1) the plan and `next3-gXX.patch`; (2) T0's seams and probes red; (3) the Forum (tag rule, tag filter in NFC, limit type, flag words); (4) the client (classifier, id seam, wrapper detail, CLI cursor, help); (5) the MCP guards, descriptions, version; (6) moved facts; (7) docs.
