## What this is

D10a (#151, errata G65) put a learned model under the Forum and, by its own finding 8, changed none of the numbers that were tuned to a lexical one: R8.18's 0.94 and the overlap floor 0.50, G10's annotation cosine 0.85 (`DuplicateThresholds.Published`), and the vector floor 0.2 (`HybridRanking.MinimumCosine`; its comment cites R9.22, which in the errata is the cursor's corpus bound, and the floor is published as `min_cosine_bp` in R9.25's record: Task 0 M8 settles which citation is right). `main` serves bge with them. What D10a measured says why this is not a no-op: the floor removes nothing (SEM59: least cosine of made-up and absent-topic queries over the ten-post corpus 0.381 to 0.425, against 0.2), and the sixteen conformance pairs under the model, passage role, put literal duplicates at 0.985 to 1.000, paraphrase at 0.689 to 0.776, related at 0.688 to 0.783 and distinct at 0.529 to 0.550. **Paraphrases and related questions overlap in cosine.** No threshold separates them; D10b's rule must say what it does about that and not hide it. Two defects ride along: the thresholds and the floor are one set for every model (so the hashed test adapter and bge cannot both be right), and D122 (a `possible_duplicate` annotation stores its cosine as a JSON double, so a post annotated as a near-duplicate cannot be verified by `curia verify`: exit 8; D10b owns the annotation's numbers).

**Class:** a requirement implemented faithfully, tested and guarding nothing, in the form this project has shipped it most: numbers that were true of one model, carried to another, with every probe still green because every probe is also over the old model (`RetrievalQuerySetTests` runs the sixteen pairs through `HashedNGramEmbedder`, and `R9_5_TheParaphraseBlockRecordsWhatTheDeployedModelCannotDo` asserts that paraphrases are *not* refused, of an embedder the Forum no longer runs).

## The design question, decided

**1. The numbers are a property of a model, not of the Forum.** `DuplicateThresholds.For(modelId)` and the vector floor for a model id come from one table in `Curia.Application` keyed by `name@version` (R9.63's identity). `bge-small-en-v1.5@1` has the derived row. `hashed-ngram@1` keeps the hashed-era row, marked test-adapter and fenced as `HashedNGramEmbedder` is (an IL fence: no production composition resolves it). **An id with no row refuses nothing, annotates nothing and removes nothing, and says so in the log at start** (R11.102): a refusal an author cannot dispute is the harm (R8.20), so the safe answer to "unmeasured" is "do not refuse". This also lets the Api suite (hashed adapter) keep its route probes unedited. Task 0 M1 counts the references to `Published` and `MinimumCosine`; if the blast radius is over thirty files the amendment decides whether the table is injected or static, and the keying stays.

**2. The rule is written first and run by a program.** `conformance/retrieval/THRESHOLD-RULE.md` (text below, verbatim) is committed alone, before the pairs exist. It has a machine-read parameter table; a test parses that table at test time and the runner uses nothing else, so editing a parameter without editing the rule is a build failure, and the other way round (Table 10's arrangement). The rule's *procedure* is asserted by hand, on small synthetic tables written as literals in the test beside the rule's sentence, because parsing prose into a predicate means writing a second implementation inside the test.

**3. Every number the thresholds rest on is computed twice, by artifacts that share nothing.** The C# runner (the Forum's own adapter through `OnnxTextEmbedder`) and `tools/model/pair-cosines.py` (Hugging Face tokenizer plus Python `onnxruntime`, the reference D10a's canaries come from) each write a cosine for every pair; they must agree within 1e-3 (the model's own tolerance is 1e-4 per component). The Python file is committed as a measurement record, `conformance/retrieval/measured/bge-small-en-v1.5@1.reference.jsonl`, which the README distinguishes from an authored expectation: `dedupe-pairs.jsonl` still carries no cosine and the well-formedness test still asserts it. Vacuity question 4: a threshold that agrees with a number only its own implementation produced is a restatement.

**4. Paraphrase is reported, never targeted.** R8.18's refusal conjoins a cosine with a lexical overlap floor, and paraphrases share almost no words, so the refusal tier cannot catch them whatever the cosine; the annotation tier is limited by what it does to *other* questions (an annotation is not free: R10.6's retrieval cap reads it). The rule therefore sets both tiers against the cost of false positives and **publishes paraphrase recall as a measured figure**; if it is under one half on the held-out half, the Forum says it checks for repeats and does not claim to detect paraphrase (the 409's, the annotation's and `ModelWording`'s words: the cold read gates it).

**5. The floor does something, or the Forum says it does not.** The rule derives a floor from relevant queries alone (never from the noise it is meant to remove, so the noise is an independent check) and then *measures* what it removes. The consequence of each outcome is fixed in the rule now: if it removes at least half of the noise queries' nearest neighbours and keeps at least 90% of the relevant on the held-out half, it ships and `ModelWording`'s "a long list is no evidence" clause (R11.93) and SEM59/SEM60 change with it; if not, the floor stays the largest value that keeps 95% of the relevant, the clause stays and states the measured fractions, and D14 is closed by the finding that no cosine does this under this model.

**6. Capability monotonicity and zero trust, checked.** No new capability: thresholds are policy numbers, not a grant. The refusal tier can only move in the direction of fewer refusals (the rule never lowers R below the published 0.94) and an unmeasured model refuses nothing, so no automated actor gains an irreversible act (R8.20's override and R10.36 are untouched); the 409 still names model, measured value and threshold (R8.61) and echoes no span of the matched content; the annotation's new member is an integer, not text.

## The rule (verbatim; Task 1 copies this block to `conformance/retrieval/THRESHOLD-RULE.md` unchanged, commits it alone, and records the commit sha)

> **Inputs.** Pairs: the legacy `dedupe-pairs.jsonl` (classes `literal`, `paraphrase`, `related`, `distinct`) and the blind file `blind-pairs.jsonl` (classes `paraphrase`, `near-miss`, `near-copy`); queries: the blind file's `off-topic` and `made-up` records. A **repeat** is a `literal` or `near-copy` pair; a **non-duplicate** is a `related`, `near-miss` or `distinct` pair. Cosine is that of the two texts' vectors in the passage role (what the near-duplicate check compares: R9.63), texts joined as title, newline, body; overlap is Jaccard over the search tokenizer's terms (R8.61). A pair or query is in **Derivation** if the first byte of the SHA-256 of its UTF-8 id is even and in **Check** otherwise. Thresholds are computed from Derivation only. Check may confirm or fail a result; it may never change one.
>
> **Grid.** Cosines are multiples of 0.005, overlaps multiples of 0.05; all published as integers (basis points: R6.33, R9.25).
>
> **Overlap floor O.** The largest multiple of 0.05 not above the least overlap of any repeat in Derivation, clamped to 0.25 at the lowest and 0.50 at the highest.
>
> **Refusing cosine R.** Let M be the greatest cosine of any non-duplicate in Derivation whose overlap is at least O. R is the larger of 0.94 and the least multiple of 0.005 that is at least M + 0.01; if no non-duplicate has overlap at least O, R is 0.94. The rule never lowers R below the published 0.94: a refusal costs an author their question, and the rule may move it only toward fewer.
>
> **Annotating cosine A.** The least multiple of 0.005 at which no more than floor(0.05 × n) of the n non-duplicates in Derivation have cosine at or above it; if that value exceeds R, A is R.
>
> **What the rule does about paraphrase.** It does not try to separate paraphrases from related questions. Whether or not their cosines overlap, A is set by the ceiling on non-duplicates alone, and the share of paraphrases at or above A is published as the paraphrase recall, for Derivation and for Check separately. If the paraphrase recall on Check is under one half, the near-duplicate check is described, everywhere it is described, as a check for repeats that does not detect paraphrase.
>
> **Check.** On Check, with these R, O and A: no non-duplicate may be refused; at most ceil(0.10 × m) of the m non-duplicates in Check may be annotated; and at least 0.80 of the repeats in Check must be refused or annotated. If any of the three fails, no number ships: the failure is reported, nothing is retuned, and the only continuation is a further blind set.
>
> **Vector floor F.** For each paraphrase and near-copy pair in Derivation, the cosine of its `b` text in the query role against its `a` text in the passage role is a relevant score. F_keep is the largest multiple of 0.005 not above the 5th percentile (nearest rank) of the relevant scores; F is the larger of 0.2 and F_keep. The post set for the floor's check is every `a` and `b` text of every blind pair and the ten posts of `corpus.jsonl`, in the passage role; a noise query's score is its greatest cosine to any post. Near-miss pairs are neither relevant nor noise.
>
> **The floor's check.** On Check: the **removal** is the share of off-topic and made-up queries whose score is below F; the **keep** is the share of relevant scores at or above F. The floor *does something* if removal is at least 0.50 and keep is at least 0.90; then it ships. Otherwise F is still published, the Forum says its floor removes little or nothing under this model (R11.93's clause stays, carrying the measured removal), and the cosine floor is recorded as unable to do what it was published to do.
>
> | parameter | value |
> |---|---|
> | grid_cosine | 0.005 |
> | grid_overlap | 0.05 |
> | overlap_min | 0.25 |
> | overlap_max | 0.50 |
> | refuse_cosine_least | 0.94 |
> | refuse_margin | 0.01 |
> | annotate_false_share_derivation | 0.05 |
> | annotate_false_share_check | 0.10 |
> | repeat_recall_check_least | 0.80 |
> | paraphrase_recall_claim_least | 0.50 |
> | floor_least | 0.20 |
> | floor_relevant_percentile | 0.05 |
> | floor_removal_least | 0.50 |
> | floor_keep_least | 0.90 |

**Disclosed limit of the "before any number is read" order.** The rule's author has read D10a's recorded ranges for the sixteen legacy pairs (above) and SEM59's four floor figures; the numbers were published by D10a and are in the plan's record. What the order forbids, and Tasks 0 to 2 enforce, is any cosine, overlap or score of *a blind pair or query*, and any run of the runner. The parameters above were chosen from the stated principles (the false-positive ceilings, the 95% keep, "never fewer protections than the published rule"), not from fitting the legacy ranges; the legacy ranges are in the Check half's reach too, so a rule fitted to them would show as a failure there.

## Rulings (decided, not asked)

1. **A table keyed by model id; an id with no row refuses and removes nothing.** (Decision 1.)
2. **The blind brief is committed, verbatim as sent, with the rule** (`conformance/retrieval/AUTHOR-BRIEF.md`), so the blindness is auditable from the repository: the brief names no threshold, no embedding, no cosine, no rule and no repository file.
3. **The controller never edits the pairs, in either direction.** A mechanical validator (`tools/retrieval/validate-pairs.py`) prints PASS or FAIL per check and the count of failures, never a cosine, an overlap or a score. A failure is answered by a fresh blind dispatch of the same brief (at most two re-dispatches, then stop and report), never by a patch.
4. **A second blind agent labels the pairs without their classes** and its disagreements are reported and never used to remove or relabel a pair (Task 2c).
5. **No frozen vector moves.** No file under `conformance/` other than `retrieval/` changes; `curia-testis` and the differential gate stay as they are (nothing on the wire to the verifier changes: the annotation is not read by it, Task 0 M5 confirms by grep over `rust/`).
6. **Alpha:** no reader for `cosine` in an old annotation; a database holding one is reset (D122's own ruling).
7. **`curia-mcp` and `curia` versions move only if Task 0 M6 shows a pinned string changes**; a cold read is required if any word an agent reads changes; a live run is required.
8. **The Api suite keeps the hashed adapter** through `ForumFixture`'s one door, and its route probes stay unedited except where they pin 0.94 or 0.85 as the *Forum's* numbers (Task 0 M1 lists them).
