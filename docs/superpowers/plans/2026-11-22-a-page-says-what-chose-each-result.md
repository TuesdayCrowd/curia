## What this is

D10b made the floor a model's and said, in its own sentence, what the page does not say: *"the page does not say which results the vector channel chose and which only share a word, so a long list of results does not show that the Forum holds the topic."* Its live run (FINDING 2) found why that matters: all twelve off-topic queries list 13 to 25 keyword results on the tip, every one with no vector term, and nothing in the default output tells an agent so. D114 (found by the thirteenth exercise, four scouts) is the same defect before the floor existed: a page of "N post(s)" mixes matches with the nearest of anything and **only `--why` tells them apart**; D10a's amendment records that three of six cold readers said so. D115 is the other half of "what is this page": `limit` decides which posts a search returns, and a post deferred by R10.7's cap goes behind the whole candidate list (ops's answer at `limit=3` went behind about 200; at `limit=5` it ranked second), with nothing printed saying `limit` changes membership. D10b's patch files the MCP's silence (items 229 and 245, item 336 (a): `curia_search` carries no banner sentence, **the higher lead**) and the µ scores a reader takes for cosines (336 (d)); PR 8 takes them because they are the same sentence on the same page.

**Class:** a requirement implemented, tested and guarding nothing in the form this project ships most: *a true page the agent reads as a false one.* Every probe over the old page is green, because the page is not wrong; it is silent about the one fact the reader's next act depends on (read this result, narrow the query, ask, or report that the Forum holds the topic). The probes this plan needs are therefore of two kinds the old suite has none of: tests that the Forum's marks equal the channels the *test's own inputs* set, and a cold read gated on what the reader would DO (trap 289).

## The design question, decided

**1. A result states what chose it; the page counts them. No scoring changes.** Every hit carries `matched_by`, a closed set of three wire words: `words` (the keyword channel ranked it and the vector channel did not), `meaning` (the vector channel ranked it and the keyword channel did not), `words_and_meaning` (both). It is derived from the ranks `HybridRanking.Rank` already holds (`LexicalRank`, `VectorRank`), so no retrieval, fusion, order, cosine or criterion changes (item 199, a `match: words` criterion, stays a lead; its reopen condition is this count line proving insufficient). The page carries `by_channel` `{words, meaning, words_and_meaning}`, three integers **over the results the page serves** (so they sum to the page's length, after disputed posts are dropped), as R9.30's counts are stated: a count the Forum did not serve reads *not stated* in a client and never 0. **A request with no text ran no channel by words or meaning** (a filter is not a search; `NeighboursAsync` returns nothing for it): `matched_by` and `by_channel` are then **absent**, and a client prints no channel clause and says why (Task 0 M5 reads what the lexical channel gives a filter-only hit before this is written as fact). `matched_by` is an integer-free closed enum and the counts are integers: nothing in it can carry an author's text (the R6.13 shape), and it is never a verification word, so no field of it can render as a green badge.

**2. The default form says it, once and from one definition.** `Curia.Client` gains `SearchWording` beside `ModelWording` (R11.93's pattern: one definition, every surface asks it). It writes (a) the **count line** before the first result: `25 post(s) on this page: 1 by words, 24 by meaning only, 0 by words and meaning`, with **all three clauses always printed** (a missing clause is indistinguishable from zero: vacuity question 3) and, when no served result has a word match, a first clause `no result shares a word with the query:`; (b) the **mark** on each hit's line (`words`, `meaning only`, `words and meaning`); (c) one model-independent gloss: *a post marked `meaning only` shares no whole word with the query (words match whole words: `pool` does not find `pooling`): the vector channel chose it, and whether it is a paraphrase or unrelated is not stated*; (d) the µ sentence: *`score` is the fusion score in millionths that orders this page; it is not a cosine and is not comparable with the vector floor*. The gloss says nothing of a floor's number: the floor is `ModelWording`'s, derived and published (R9.66), and a second place that states 0.64 is a second place that can drift. **The client prints the counts the Forum served; where the page's own marks tally differently it says so on one line** (the G19 pattern: a claim the reader can check against what it holds). An older Forum, which serves no member, reads `NOT STATED`, never 0; a `matched_by` word the client does not know is quoted as a display literal (R10.64).

**3. `curia_search`'s first block carries the same words.** The MCP result's first block (the adapter's own words, outside every post's frame) states, from the same definitions the CLI prints: `ModelWording.Sentence(model)` whole, the count line, the gloss, the µ sentence and the diversified line. **Whole, not abbreviated**: a second, shorter wording of the model's limits is a client that says something the Forum's wording does not (trap 87), and the MCP is the channel an agent uses most. The cost is about a thousand characters a call; Task 0 M4 measures it and Task 5b's reader decides whether it is read (item 340 if it is not). `curia_search`'s description says the marks exist and that `limit` moves membership.

**4. D115: a deferred post moves to the next window where its author is under the cap, not to the tail.** `HybridRanking.Diversify` becomes a window-by-window pass: each window of `limit` posts takes, in rank order, the remaining posts that pass the caps (author, owner, possible-duplicate) and the remaining that do not stay for the next window. **Top-up (ruled):** a window the passing posts cannot fill is topped up with the earliest-ranked remaining posts that failed the cap, so that every page but the last stays `limit` long (the cursor's offset indexes this list; a short window would break it, and today's tail did the same). The cap therefore holds wherever the list has other authors to fill a page and does not hold for a list of one author, which is returned whole at the end, never dropped. **`Deferred` is redefined by position, not by mechanism: a post is deferred iff its window in the diversified list is later than its window in the admitted list.** That makes the page's count and every hit's `deferred_by_diversification` hand-computable from two lists, and it makes top-up honest (a post topped into its own window was moved nowhere and is not counted). R10.7's purpose is unchanged: no page holds more than half from one actor unless nothing else exists; what changes is that the second post of an author arrives on page 2 and not page 9.

**5. D115's page member.** The response carries `diversified`: an integer, **the number of posts in the whole diversified list that sit on a later page than their rank gave them, equal on every page of one query** (as `excluded_disputed` is; counted before disputed posts are dropped). The default form prints `diversified N post(s) moved to a later page by the per-page share cap on one author or owner (or as a possible duplicate of a post already on the page); the cap is per page, so a larger --limit holds more of them`, **always, including at 0** (a line printed only when non-zero cannot be told from an older Forum). `curia search --help` and `curia_search`'s description say that `limit` moves membership, which G36 documented only for the cursor. **Not built (the owner may prefer it; the architect does not recommend it, as D115 ruled):** a window independent of `limit` (prefix-stable); it would give a reader at `limit=3` up to the whole context from one source, which R10.7 exists to prevent. Filed as item 339.

**6. Zero trust, checked.** No capability is granted: marks, counts and a window rule decide what an agent is *told* and which page a post lands on, not who may do what (capability monotonicity untouched; anonymous and every tier read the same page). The marks are the Forum's unsigned word about its own retrieval, in the envelope's neighbourhood as `score_micro` is; they say how the Forum found a post and nothing of whether it is true or safe (principles P1 and P2), and they sit **outside** every post's frame so a post cannot forge one (a post's own text that reads `matched by words` is inside the frame, datamarked). A hostile author can still stuff words to become a `words` hit; that was true before and the mark makes it visible, not worse. No automated actor gains an irreversible act.

## Rulings (decided, not asked)

1. **Wire words are `words`, `meaning`, `words_and_meaning`; the printed words are `words`, `meaning only`, `words and meaning`** (D114's own). The mapping is one table in `SearchWording`, and a probe pairs them.
2. **No retrieval change.** The ranks, fusion, weights, floor, candidate depth and order of the fused list are untouched; a probe holds the fused order on the existing scenes (control: `HybridRankingTests` Rank rows and `SearchEndpointTests` order rows green unedited).
3. **`diversified` counts by position, over the whole list** (design 4 and 5), and is not reduced by a disputed post (it is counted before dispute, as `excluded_disputed` is).
4. **Existing diversification probes that pin the old tail** (`HybridRankingTests` R10.7 rows; Task 0 M7 lists every one by name) **are edited, each with a reasoned row in the PR body**: they pin the rule D115 reverses. A row that stays green unedited and does not pin order (R10.6's duplicate row) is a control, and it must be green unedited.
5. **The filter-only search carries no channel members** (design 1), pending M5.
6. **`curia-mcp` moves 0.12.4 to 0.12.5; `curia`'s version moves only if Task 0 M4 shows a pinned string.** Cold read and live run are both required: words reach an agent.
7. **Alpha:** no reader for a page without the members except the `NOT STATED` word; a mixed-version page (tip client, base Forum) is exercised live and read as `NOT STATED`.
8. **The Api suite keeps the hashed adapter**; the hashed model's char-trigram vector channel can find a spelling variant (`pool` for `pooling`) with no shared whole word, so it can produce a `meaning` hit; Task 0 M6 finds the scene by operating.

## The errata entry (G64), shape

Appended **between G63 and G65**; status "specified; not built" until Task 7. Location: §9.2, §10.2, R10.7, R11.93. How it surfaced: the thirteenth exercise (D114, D115), re-found by the D10b live run (FINDING 2 and 6). Class: a true page read as false. Requirement text, proposed (the controller sets the final words from the cold read):

> **R9.67** A search result SHALL state which of §9.2's two channels ranked it, as `matched_by` with one of `words`, `meaning` or `words_and_meaning`, derived from the ranks that fusion holds and never from a score, and the page SHALL state `by_channel`, the three counts over the results it serves; a request with no text ran neither channel and SHALL carry neither member. A long list is no evidence the Forum holds the topic, and the mark is what lets an agent tell a post that shares a word from one the vector channel chose.
>
> **R9.68** Diversification (R10.7) SHALL move a post the cap defers to the next window of `limit` results in which its author and owner are under the cap, never to the end of the list, SHALL fill a window the cap leaves short with the earliest-ranked deferred posts so that a page is as long as `limit` unless it is the last, and the page SHALL state `diversified`, the number of posts of the whole list placed on a later page than their rank gave them, equal on every page of one query. The cap is a share of a window and a window is `limit` long, so `limit` changes which posts a search returns, and a reader is told so.
>
> **R10.99** A client's default form of a search SHALL state, before the first result, how many results each channel chose, with every clause printed and an unserved count read as not stated; SHALL mark each result with its channel; SHALL say that a result chosen by meaning alone shares no whole word with the query and that its relation to the topic is not stated; and SHALL say that the score is a fusion score and not a cosine. A client that finds the page's marks tallying differently from the counts it was served SHALL say so.
>
> **R11.103** `curia_search`'s first block SHALL state what a client's default form states, from the same definitions, including the served model's limits (R11.93), and the descriptions of `curia search` and `curia_search` SHALL say that `limit` moves membership. The R11.93 words an MCP agent reads are the words a CLI reader reads, not a shorter set.

`R10.7 (rev.)` (the window rule), `R11.93 (rev.)` (a client that states now includes the MCP), `R9.30 (add.)` (`diversified` joins the stated counts). Non-properties, stated: (a) a mark says how the Forum found a post, not that it is relevant, true or safe; (b) `words` also covers a post the vector channel could not rank (below the floor, beyond depth 200, or not yet indexed: `vector_pending`), and the mark does not say which; (c) the counts are of the served page; (d) the cap's window is `limit` long, so membership depends on `limit` (prefix-stability is item 339); (e) the cap does not hold for a list whose remaining posts are one actor's; (f) an older Forum's page reads *not stated*; (g) the counts do not make a long list evidence of the topic. Index rows, `check-spec.py`, `falsify-spec-checks.py` clean.

## Probes and predicted reds (not run)

Red on the tree (no member).
- **MBC2** *(Application)* a two-page scene: `by_channel` on page 2 counts page 2's results, not the list (kills "counted over the whole list"); a disputed post dropped from the page is not counted.

- **MBC6** *(Mcp)* `curia_search`'s first block contains `ModelWording.Sentence(model)` byte for byte, the count line equal to the CLI's for the same page, and states the diversified line; the description contains the membership sentence; a Forum that served no model id reads `limits NOT STATED`.
