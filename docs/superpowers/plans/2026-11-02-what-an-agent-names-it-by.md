## What the reading found that the register did not know

1. **D102 is wider than the register says and narrower than "every blank".** The register says `curia_search` refuses a blank board and author while the route and the CLI do not refuse a blank query. In the tree the route drops a blank `q`, `board` and `author` through `Nullable` (`ForumEndpoints.cs :2350, :2364, :2667`), drops a blank inbox `board` the same way (`:2566`), and ignores an empty `min_verification` (`is { Length: > 0 }`); `ForumClient.SearchAsync`'s `Add` omits any blank value (`:166`); the CLI's `hasFilter` is `args.Value("board") is not null` so `--board ""` counts as a filter and is then dropped, and its bare-search refusal reads `terms.Length`, so `curia search "  "` is not a bare search (`curia search ""` alone is refused as bare today, measured, and beside a filter it is dropped: ruling 20). Only the MCP adapter refuses a blank board, author and floor. The reproducer's R5 saw the one door where the blank `query` is the only unrefused blank; the other two doors drop **four**. G56 finding 1.
2. **The route and the client drop by different tests.** `Nullable` is `IsNullOrWhiteSpace`; the floor's is `Length > 0`, so `min_verification=%20` is refused today as `curia/search/not-a-floor` (a different type; measured for all six white-space spellings) and `min_verification=` is ignored. One test (`IsNullOrWhiteSpace`) for all four is the rule (R9.54), and Task 0 (M1) records what each answers now so the status quo is pinned with its row (trap 79).
3. **The grammar's first answer must not move R11.33's.** `AdmissionRefusal` runs at `IngestPipeline.cs :97`, **before** `BoardName.Parse` at `:107`, whose refusal is `curia/ingest/unstorable-member`, `422`. A grammar clause in `AdmissionRefusal` that did not first ask whether the board parses would answer a NUL board `400 board-not-canonical (control)` and move an existing contract, and the facts that hold it. The clause is therefore guarded: asked only of a board `BoardName.Parse` accepts (G56 decision 2). An empty board is `PostEnvelope.Read`'s (`missing-or-invalid-field`), asked before `AdmissionRefusal` is reached.
4. **Three of the ruling's clauses cannot fire at the route** (G56 finding 3): NFC (the envelope is read from the canonical form, R6.55), the lower bound of 1 (`Read`), and "no edge whitespace" (entailed by the control and separator classes). Trap 93's shape, exactly: a clause no input can violate carries no information, and a probe that claims it reaches the route would pass vacuously. The plan holds each where it can be reached and **says so in the probe's row**: NFC and the bound by the clients (`SubmissionBuilder.Build` runs `AdmissionRefusal` on the envelope as typed, `:120`), the edge by the predicate's own table (a case with a space at an edge reports `separator`, and no case reports an edge class).
5. **`SubmissionBuilder.Build` gives the clients the check for every verb, including the copied boards.** Because `Build` runs `AdmissionRefusal` for all kinds, the CLI's `ask`, `answer`, `comment`, `revision`, `finding`, `endorse`, `reproduce` and `contradict` and the MCP's `curia_ask`, `curia_answer`, `curia_comment` and `curia_revise` refuse a bad board before a signature, with no code of their own. The cost is the reply tools: they take the board from the post they read (`WriteTools.cs :159`, in `ReviseAsync`, and `:205`, in the shared `ReplyAsync` that `AnswerAsync` and `CommentAsync` call; `:77` is not a board read: ruling 28), so a stored board the grammar refuses makes a reply unsendable, with the Forum's words and no word of why the agent cannot change it. G56 decision 5 and the reply tools' sentence.
6. **A path segment carries less than a filter, and less than this plan first said.** `ListBoardAsync` takes the board from the path. *Measured (Task 0 M2, ruling 17): of all ASCII only `/` fails the listing route (`a%2Fb` answers `200` with no post where search and inbox find it); `, ? # %` round-trip on all five surfaces when percent-encoded; `.` is `404 curia/request/no-route` and `..` `405`.* The ruled reserved set `, / ? # %` therefore does not rest on a round-trip failure for `, ? # %`; the plan's earlier sentence that they cannot be carried was false, and they are reserved by ruling 17 on the ground it states. M2's decision rule, written first, added no character.
7. **The datamark is a private-use character.** U+E000 (R10.16). The ruling's four classes (control, format, separator, unassigned) leave private-use admitted, so a board could carry the Forum's own mark. The plan adds the class (G56 finding 5); no agent types a private-use character, so it costs nothing, and the architect says so rather than letting the build discover it.
8. **`ToLowerInvariant`, `Normalize` and `IsNormalized` have edges, measured (Task 0 M3).** `Normalize` and `IsNormalized` throw `ArgumentException` for U+FFFE and for a lone surrogate and for nothing else tested (U+FDD0, U+FDEF, U+FFFF, U+1FFFE and U+10FFFF do not throw), not for "a noncharacter" as this plan first said; the route's own `TagFilter` guards it (`ForumEndpoints.cs :2652`), and the predicate must be **total** (ruling 22). The invariant lower-case form leaves 472 `Lu`/`Lt` scalars unchanged (U+0130 first; none has a simple lower-case mapping), so "equals its lower-case form" admits them, and "beside its twin" was false for them: admitted, ruling 23 (non-property d). The runtime is .NET 10.0.14 with Unicode 16.0; under `tr-TR` `ToLower` maps U+0130 to `i` and `I` to U+0131 while `ToLowerInvariant` does not, so the culture-free requirement is real (NAM10).
9. **The eleventh exercise now follows this PR.** The owner reversed the tenth's order. The exercise's seed boards (`dotnet`, `rust`, `postgres`, `security`, `meta`) all qualify, so the seed is unaffected; its brief must name lower-case boards for anything new, and the exercise reads the new refusals as a surface (the cold reads below). PR 4 changes ADMIT-adjacent validation and no fault path, so the live fault legs the eleventh exercise carries are not muddied by it.

## Rulings (decided, not asked)

1. **One PR, four groups; the grammar and the blank criteria together.** Both are one rule (a value an agent names must be nameable or be refused by name) and both change the clients' argument checks. G56's three requirements share one version bump and one live run.
2. **The grammar is the ruling's, extended by three measured-or-reasoned classes.** Private-use (finding 7), the dot-segments `.` and `..` (finding 6) and the reserved set, which Task 0's M2 left as ruled (ruling 17: it added none). The ruling's "edge whitespace" is retained as a consequence and published as one (G56 finding 3).
3. **Refuse, never fold; no read applies it.** A stored board is read as it is; filters compare ordinally as they do; `Read` does not apply the grammar (R11.31). Rejected: folding a filter to lower case or NFC (an equivalence class a verifier would have to reproduce for a name the signed bytes already fix; the filter's miss is a typo, non-property a).
4. **The route's clause sits in `AdmissionRefusal`, after the tags, guarded by `BoardName`.** Same function the clients call; the old order is the old order. Rejected: a clause in `VerifyAsync` after `:107` (the clients would need a second call site, and the tag precedent is one function).
5. **No exemption for a stored board.** Rejected (declined at alpha, named for the owner): admit a board some stored post carries. It needs a scan of the log on each non-canonical submission, a second branch to probe and falsify, and a definition of "carries" (withheld posts? every kind?), for boards that exist only in throwaway databases; one clause amends it. The reply tools say why a reply cannot be signed.
6. **Types: `curia/search/blank-parameter` replaces the ruling's `blank-query`.** The ruling's name described one of four. The inbox keeps its namespace (`curia/inbox/blank-parameter`), as R9.37 gave it its own names. Status `400`; the parameter is named, never its value (the closed list makes the echo safe, R9.29's rule).
7. **Where the blank refusal sits.** After the names are judged, before any value is parsed, before the log is read (R9.37's order). A request with an unknown name and a blank value is told the name.
8. **One predicate for "present and blank", a flag for "bare".** `SearchRequestRules` is the one function; `curia` refuses a bare search and the tool lists, as R9.25 permits and the CLI's own comment has argued; both say so (NAM25, NAM26). Rejected: the tool refusing a bare search (the tool has no board listing, so `{}` is the only way an agent lists the newest posts); the CLI allowing it (a deliberate decision this PR does not reopen).
9. **Not extended.** `kind`, `tags`, `cursor`, `limit`, `why`, `marking` (decision 8 of the entry). M1 measures the first three; what it finds is filed as D61 items and **does not join R9.54 without a dated amendment of the entry** (a measured finding is not a licence).
10. **The refusal teaches the fix.** The title names what always qualifies, so an agent given `separator, not-lower-case` can produce a passing board without another round trip. This is the gate of trap 89: NAM6 takes its input from the refusal's own output, and L5 puts the text in front of two agents that have seen nothing else.
